빠른 시작Quick Start

Node.js 20.9 이상이 설치된 PC에서 아래 순서로 실행합니다. 처음 받은 경우 npm install을 먼저 해야 합니다.

터미널 · medical-dermatology 폴더에서
npm install          # 라이브러리 설치 (처음 1회, node_modules 생성)
npm run dev          # 개발 서버 → http://localhost:3000/project/medical-dermatology
npm run build        # 배포용 빌드 (오류 검사 포함)
# 빌드 결과는 out/ 폴더 — 폴더 안 파일 전체를 웹호스팅에 업로드
npm run lint         # 코드 규칙 검사

개발 서버가 켜져 있는 동안에는 파일을 저장하면 브라우저에 바로 반영됩니다. 새로고침할 필요가 없습니다.

기술 네 가지가 층층이 쌓여 있고, 맨 아래에서 Node.js가 전체를 실행합니다. 위층일수록 사용자 눈에 가깝습니다.

3

기술별 역할How Each Piece Is Used

TypeScript: 데이터 형태를 약속

JavaScript에 타입(자료의 형태)을 더한 언어입니다. 브라우저는 빌드 과정에서 변환된 JavaScript를 읽습니다. src/data/treatments.ts의 Treatment 타입이 진료과목 하나가 가져야 할 항목을 정합니다. 과목을 추가하면서 필드를 빠뜨리거나 오타를 내면 에디터와 npm run build가 바로 오류를 냅니다.

src/data/treatments.ts
export type Treatment = {
  slug: string;        // 주소에 쓰이는 이름 → /treatments/lifting
  category: "aesthetic" | "medical";
  ko: string;          // 화면에 보이는 이름
  recommend: string[]; // 이런 분께 권합니다
  ...
};

React: 화면을 부품으로 조립

  • 컴포넌트 재사용: PageHero 하나를 서브페이지 8개 상단에서 공통으로 씁니다.
  • Props: <PageHero title="의료진" />처럼 내용만 바꿔서 넘깁니다.
  • 반복 렌더링: treatments.map(...)이 데이터 8개로 카드 8개를 자동으로 만듭니다.
  • State: 모바일 메뉴 열기/닫기, 공지 배너 닫기, TOP 버튼 표시가 useState로 동작합니다.

Next.js: React를 웹사이트로

  • 폴더가 곧 주소: src/app/about/page.tsx는 /about이 됩니다. 라우터 설정 파일이 따로 없습니다.
  • 동적 라우트와 정적 생성: treatments/[slug] 폴더 하나와 generateStaticParams()로 상세 페이지 8개를 빌드할 때 HTML로 미리 만듭니다. 속도와 검색 노출에 유리합니다.
  • 서버 컴포넌트와 클라이언트 컴포넌트: 기본은 서버에서 HTML로 완성되는 서버 컴포넌트입니다. 사용자 조작이 필요한 파일만 첫 줄에 "use client"를 붙였습니다(Header, TopBanner, FloatingContact, Reveal).
  • 내장 최적화: next/image가 사진 크기를 줄이고 형식을 변환합니다. next/font는 폰트를 최적화하고, metadata는 페이지별 검색 제목과 설명을 붙입니다.

Tailwind CSS: 클래스 단어로 꾸미기

CSS 파일을 따로 길게 쓰지 않고 태그에 짧은 스타일 단어를 붙입니다. md:, lg: 접두어로 화면 크기별 레이아웃을 한 줄에서 처리합니다.

예시
<a className="h-12 bg-ink px-7 text-ivory hover:bg-gold-deep">
// 높이 48px · 차콜 배경 · 좌우 여백 · 아이보리 글씨 · 마우스를 올리면 골드

<ul className="grid sm:grid-cols-2 lg:grid-cols-3">
// 모바일 1열 → 태블릿 2열 → PC 3열

이미지 · 영상 저장 경로Where Files Go

사진과 영상은 모두 public/ 아래에 정해진 이름으로 저장합니다. 같은 이름으로 덮어쓰면 교체됩니다. 이미지 생성(ChatGPT)을 맡길 때는 아래 표와 지시문을 그대로 전달하면 됩니다.

사이트 반영 상태: 생성 대상 이미지 10장은 아래 경로에 저장하고 메인·병원소개 페이지에 연결했습니다. 같은 이름으로 파일을 교체하면 반영됩니다. 의료진·병원 공간·장비는 실제 사진을 준비한 뒤 별도 연결이 필요합니다. 영상은 이미 연결되어 있습니다. 제작 이미지 10장 보기

저장 규칙

  • 위치: public/images/섹션/파일명.jpg. 영상과 포스터는 public/에 둡니다.
  • 파일명: 영문 소문자와 하이픈만 씁니다. 공백과 한글은 쓰지 않습니다. 확장자는 표와 똑같이 .jpg로 맞춥니다.
  • 크기: 표의 크기에 정확히 맞춥니다. 화면에 따라 잘려 보이는 칸이 있으니, 중요한 피사체는 가운데에 둡니다.
  • 용량: 이미지는 500KB 이하, 영상은 5MB 이하로 줄입니다. 사이트가 화면 크기에 맞게 다시 최적화합니다.
  • 원본 보관: 생성 원본, PSD, 촬영 원본은 프로젝트 밖(구글 드라이브 등)에 보관합니다.

ChatGPT로 만들 때 알아둘 점

  • ChatGPT가 만드는 이미지 크기는 정사각형, 가로형, 세로형 몇 가지로 정해져 있습니다. 표와 비율이 가까운 방향으로 만든 뒤, 같은 대화에서 "지정 크기로 잘라서 JPG로 저장해 줘"라고 요청하면 크기를 맞출 수 있습니다.
  • 이미지 안에 들어간 글자는 알아보기 어렵게 깨지는 경우가 많습니다. 글자는 사이트가 얹으니 이미지에는 넣지 않습니다.

[브랜드 톤]
- 청결하고 세련된 프리미엄 피부과. 색은 아이보리, 따뜻한 베이지, 은은한 샴페인 골드.

[반드시 지킬 것]
- 이미지 안에 글자, 로고, 워터마크를 넣지 않는다. (사이트가 글자를 얹는다)

[파일 규격]

주의사항Known Pitfalls

Next.js 16은 예전 버전과 다릅니다

검색으로 찾은 예제가 구버전 문법일 수 있습니다. 공식 문서가 node_modules/next/dist/docs/에 같이 설치되어 있으니 그것을 기준으로 삼습니다.

  • 동적 페이지의 params는 Promise라서 const { slug } = await params로 꺼냅니다.
  • page.tsx 파일에서는 페이지 컴포넌트와 정해진 설정(metadata, generateStaticParams 등)만 export할 수 있습니다. 공용 부품은 components/에 둡니다.

외부 이미지는 허용 목록에 등록해야 합니다

next.config.ts의 remotePatterns에 없는 사이트의 이미지를 쓰면 해당 페이지 전체가 500 오류를 냅니다. 개발 중에 실제로 이 오류가 났었고, 쿼리스트링이 붙은 주소도 통과하도록 객체 형식으로 적어 해결했습니다.

next.config.ts
images: {
  remotePatterns: [{ protocol: "https", hostname: "images.unsplash.com", pathname: "/**" }],
}

주소 접두어 (basePath)

로컬에서 project/ 안의 다른 Next.js 사이트와 구분하려고 next.config.ts에 basePath: "/medical-dermatology"를 설정했습니다. http://localhost:3000으로 들어오면 이 주소로 자동 이동합니다.

  • next/link의 링크는 접두어가 자동으로 붙으므로 코드에는 /about처럼 적습니다.
  • public/의 사진을 next/image로 쓸 때는 src 앞에 /medical-dermatology를 직접 붙여야 합니다.
  • 실제 도메인 루트에 배포할 때는 BASE_PATH를 ""로 바꾸고 redirects 설정을 지웁니다.
  • 다른 Next.js 사이트를 동시에 켜려면 포트를 다르게 줍니다. 예: npm run dev -- -p 3001

폰트 굵기를 늘리면 CSS가 커집니다

한글 폰트는 글자 범위별로 @font-face가 90여 개씩 생깁니다. 나눔명조는 400 굵기만 쓰도록 줄여 두었습니다(app/layout.tsx). 굵기를 추가하면 첫 화면이 느려지니 꼭 필요할 때만 늘립니다.

공유 이미지는 og/route.tsx로 만듭니다

Next.js의 opengraph-image 파일 규칙은 basePath를 주소에 넣지 않아서, 주소가 404가 됩니다. 그래서 일반 경로(/og)로 만들고, seo.ts의 OG_IMAGE로 모든 페이지에 지정했습니다.

스크롤 등장 효과에 "이미 처리함" 표시를 달지 않습니다

개발 모드에서는 React가 effect를 두 번 실행합니다. Reveal.tsx가 요소에 처리 표시를 남기면, 두 번째 실행이 그 요소를 건너뛰어 콘텐츠가 투명한 채로 남습니다(실제로 발생했던 버그). 같은 요소를 여러 번 관찰해도 문제가 없으니 표시 없이 관찰합니다.

"use client"는 필요한 곳에만

useState, useEffect, 클릭 이벤트를 쓰는 파일에만 붙입니다. 필요 없는 파일에 붙이면 브라우저로 보내는 JavaScript가 늘어 페이지가 무거워집니다.

스크롤 애니메이션 (data-reveal)

요소에 data-reveal 속성을 붙이면 스크롤할 때 떠오릅니다. JavaScript가 동작할 때만 숨김 상태에서 시작하므로(html.js 클래스) 스크립트가 꺼져 있어도 내용은 보입니다. OS에서 동작 줄이기를 켠 사용자에게는 애니메이션이 꺼집니다.

의료광고 규정

의료법 제56조: 치료 경험담(후기)과 시술 전후 사진은 광고 제한 대상이라 일부러 넣지 않았습니다. 추가하려면 먼저 의료광고 사전심의 대상인지 확인해야 합니다. 부작용 안내 문구는 지우지 않습니다.

node_modules 폴더Dependencies

Next.js, React, Tailwind 같은 외부 라이브러리의 실제 코드가 설치된 폴더입니다. 라이브러리가 또 다른 라이브러리를 필요로 하기 때문에 현재 기준으로 최상위 폴더만 289개, 용량은 약 439MB입니다.

파일비유역할
package.json장보기 메모필요한 라이브러리 목록과 실행 명령어
package-lock.json영수증정확한 버전까지 고정. 누가 설치해도 같은 결과
node_modules/사 온 물건실제 설치된 코드. 언제든 다시 만들 수 있음
  • 개발하고 빌드할 때는 꼭 필요합니다. 없으면 npm run dev가 실행되지 않습니다.
  • 지워도 됩니다. npm install 한 번이면 똑같이 다시 생깁니다. 이상한 오류가 날 때 지우고 다시 설치하는 것이 흔한 해결법입니다.
  • Git에 올리지 않습니다. .gitignore에 이미 제외되어 있습니다.
  • 압축해서 넘길 때도 뺍니다. 받는 쪽에서 npm install을 실행하면 됩니다. package-lock.json은 반드시 함께 넘깁니다.

방법적합한 경우필요한 작업
Vercel가장 간단함. Next.js 제작사의 호스팅Git 저장소 연결만 하면 설치·빌드를 서버가 알아서 함

정적 내보내기의 제약: 이미지 자동 최적화가 꺼지므로 사진은 미리 적당한 크기(가로 1600px 이하, WebP 권장)로 줄여서 넣습니다. 현재 사이트에는 서버 기능(API, 폼 저장)이 없어서 정적 내보내기가 가능합니다.
