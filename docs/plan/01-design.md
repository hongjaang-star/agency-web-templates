# 에이전시 템플릿형 홈페이지 구축 설계안

문서 버전 v1.2 (2026-10-02). 이 탭은 설계 기준이며, 운영 세부 사항은 각 탭에서 관리합니다. 변경 이력은 이 탭 끝에 기록합니다.

## 현재 결정 사항 요약

- 프론트: Next.js 정적 export(out/ 폴더 HTML)로 표준화. Node 서버 없이 일반 호스팅에 업로드 가능.
- 동적 기능: 상담폼, 문의게시판, 예약은 PHP + MySQL 공통 API 하나로 만들어 모든 사이트가 공유.
- 콘텐츠 수정: 초기에는 에이전시 유지보수 계약으로 처리(data 파일 수정 후 자동 배포). 관리자 기능은 수요가 쌓이면 추가.
- 명명 규칙: 업종 슬러그는 {대분류}-{업종} 형식의 영문 소문자 kebab-case. 같은 업종의 시안은 콘셉트 이름의 변형(variant)으로 구분.
- 첫 템플릿: GitHub hongjaang-star/medical-dermatology (피부과, 변형 lumiere). 섹션 블록 분리, 업종 설정 data 이동, 정적 export, 생성 스킬 문서화 완료.
- 운영 목표: 90일 안에 포트폴리오 45개, 유지보수 구독 9곳(가정치). 난이도는 L1~L5 레벨로 단계 확장하고, 레벨이 곧 상품 등급.
- 운영 문서: 운영계획, 생산 파이프라인, 사이트 스펙 표준, 자동화 시스템, 마케팅과 수익화는 각 탭에서 관리.

## 요구사항 분석과 보완점

| 구분 | 원 요구사항 | 보완 필요 사항 |
|---|---|---|
| 생산 기준 | 하루 1개 생성 | 완성 기준(DoD)을 정한다. 페이지 수, 필수 섹션, QA 통과 기준이 없으면 품질이 일정하지 않다. |
| 포트폴리오 목적 | 업종별 홈페이지 등록 | 데모 사이트는 영업 도구다. 각 데모에 "이 템플릿으로 견적 문의" 전환 경로를 둔다. |
| 콘텐츠 | 언급 없음 | 가상 업체명, 카피, 이미지 출처를 정한다(AI 생성 이미지 또는 상업용 무료 스톡). 실존 업체 사이트는 모방하지 않는다. |
| SEO | SEO 충족 | 구글과 네이버 서치어드바이저를 모두 대응한다. 로컬 업종은 구조화 데이터(LocalBusiness)와 네이버 플레이스 연계가 핵심이다. |
| 법적 요건 | 없음 | 상담·예약 폼에는 개인정보 수집·이용 동의와 개인정보처리방침 페이지가 필수다. 병의원은 의료광고법, 법률사무소는 변호사 광고 규정을 검토한다. |
| 접근성 | 없음 | 공공·기관 고객을 고려해 웹접근성(KWCAG) 기본 준수를 템플릿 단계에서 반영한다. |
| 유지보수 | 관리 편의성 | 디자인과 콘텐츠를 분리한 구조를 전제로 한다. |
| 성과 측정 | 없음 | GA4와 네이버 애널리틱스를 기본 탑재하고 폼 제출과 전화 클릭을 전환 이벤트로 잡는다. |

## 업종별 레퍼런스 조사 방법

업종마다 같은 양식의 리서치 카드 1장을 만들고, 이것을 사이트 생성의 입력값으로 쓴다. 양식은 저장소의 skills/site-template/research-card.md.

조사 소스는 GDWEB, 웹어워드코리아 수상작, Awwwards, 해당 업종 네이버 검색 상위 10개 업체 사이트다. 카드에는 업종 목표, 주요 타깃, 핵심 CTA, 필수 섹션과 순서, 디자인 경향, 타깃 검색 키워드("지역명 + 업종"), 업종 규제를 기록한다.

## 명명 규칙과 저장소 구조

- 업종 슬러그: {대분류}-{업종}, 영문 소문자 kebab-case. 대분류는 pro, space, food, studio, biz, edu, service, medical, fitness, beauty, stay, event, auto.
- 변형: 번호 대신 콘셉트 이름(luxe, clean, soft, expert, lumiere 등). 디자인과 섹션 순서만 다르면 변형, 목표나 핵심 섹션 구성이 절반 이상 다르면 별도 슬러그.
- 데모 URL: demo.회사도메인/{슬러그}/{변형}. 데모 페이지는 noindex, 검색 노출은 본 홈페이지의 포트폴리오 목록 페이지가 담당.
- 저장소: 현재는 업종별 저장소(medical-dermatology). 업종이 3개 이상 쌓이면 agency-web-templates 모노레포로 합치고 공통 코드를 packages/core, packages/blocks로 분리.
- 고객 납품 사이트: site-{고객명} 저장소.

## 템플릿 구조 설계

원칙은 셸, 섹션 블록, 업종 설정, 테마 토큰 4개 레이어의 분리다. 새 사이트 제작은 코드 작성이 아니라 데이터 작성이 되도록 한다.

| 레이어 | 위치 (medical-dermatology 기준) | 역할 |
|---|---|---|
| 셸·공통 코드 | src/lib, src/components | 레이아웃, 헤더·푸터·로고, SEO 출력, 구조화 데이터. 업체명·업종명 하드코딩 금지. |
| 섹션 블록 | src/components/blocks | 메인 섹션 12개와 레지스트리(index.ts). |
| 업종 설정·콘텐츠 | src/data | 업체 정보, industry(schema.org 타입, 전문가 호칭), homeSections(섹션 순서), 서비스·구성원 데이터. |
| 테마 | src/app/globals.css의 @theme | 색상, 서체, 모션 토큰. |

### 공통 모듈 사양

| 모듈 | 내용 |
|---|---|
| 지도 | 카카오맵 또는 네이버 지도, 주소 입력만으로 표시 |
| 상담·견적 | PHP 공통 API로 접수, 관리자 메일 알림(추후 카카오 알림톡), 개인정보 동의 필수 |
| 예약 | 날짜·시간 슬롯, 관리자 승인 방식으로 시작. 네이버 예약 링크 방식도 선택지로 유지 |
| 문의게시판 | 비밀글, 관리자 답변, 스팸 방지(허니팟과 reCAPTCHA) |
| 플로팅 CTA | 모바일 하단 전화, 카카오톡 채널 버튼 |

### SEO 기본 탑재 항목

페이지별 title, description, canonical, OG 태그. JSON-LD 구조화 데이터(업종 타입). sitemap.xml과 robots.txt 자동 생성. 시맨틱 HTML(h1 1개). 이미지 WebP와 alt 필수. Lighthouse 성능·SEO·접근성 90점 이상.

## 기술 스택 결정: Next.js와 PHP 비교

| 비교 항목 | Next.js | PHP |
|---|---|---|
| SEO·성능 | 정적 생성으로 빠르고 메타·sitemap·구조화 데이터 자동화가 쉬움 | SEO는 동등, 캐시 없으면 속도는 약간 불리 |
| AI 생성 적합성 | 컴포넌트·타입 구조라 블록 생성과 수정 오류가 적음 | HTML과 PHP 혼재 코드는 일관성 유지가 더 어려움 |
| 호스팅 | 정적 export로 어떤 호스팅에도 업로드 가능 | 국내 거의 모든 호스팅에서 동작 |
| 폼·게시판·예약 | 별도 백엔드 필요 | 자체 구현이 쉬움 |
| 고객 직접 수정 | 관리자 없음, 빌드 필요 | 관리자 페이지 구현이 자연스러움 |
| 인수인계 | 국내 소형 업체 중 유지보수 가능한 곳이 적음 | 국내 에이전시 표준 |

결론: 프론트는 Next.js 정적 export로 표준화하고, 폼·게시판·예약은 PHP + MySQL 공통 API로 보완하는 하이브리드 구조.

### 자동화 고도화 단계

- 1~2주차: 수작업 진행, 프롬프트와 체크리스트 문서화, 블록 라이브러리 확충.
- 3~4주차: 반복 작업을 Claude 스킬로 정리(skills/site-template/SKILL.md). 리서치 카드를 넣으면 데이터 파일, 카피, SEO 메타를 생성.
- 2개월차 이후: GitHub Actions로 커밋 시 자동 빌드·배포와 Lighthouse 검사.

## 착수 순서

블록 재사용률이 높은 순서로 진행한다. 세무사무소, 법률사무소, 노무사무소(전문직 구조 재사용), 인테리어, 건축사무소(갤러리 블록 확립), 카페, 사진 스튜디오, 중소 제조기업, 청소·방역, 컨설팅. 피부과는 이미 완료되어 2단계 병의원 계열의 기준 템플릿으로 쓴다.
