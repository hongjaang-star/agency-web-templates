# 운영계획

이 탭은 90일 운영 목표, 난이도 레벨 체계, 로드맵, 주간 운영 리듬, 역할 분담, 리스크를 다룬다. 세부 실행 절차는 생산 파이프라인, 자동화 시스템, 마케팅과 수익화 탭에서 관리한다.

## 운영 목표 (90일)

90일 안에 영업 가능한 포트폴리오를 쌓고, SNS 유입에서 첫 계약과 유지보수 구독 매출을 만드는 것이 목표다. 아래 수치는 초기 가정치이며 4주 단위로 실제 지표를 보고 조정한다.

| 지표 | 30일 | 60일 | 90일 |
|---|---|---|---|
| 공개 포트폴리오 수 | 15개 | 30개 | 45개 |
| 운영 레벨 | L1 | L1~L2 | L2~L3 |
| SNS 게시물 | 주 5회 이상 | 주 7회 | 주 10회 |
| 포트폴리오 사이트 방문 | 기준치 측정 | 월 1,000회 | 월 3,000회 |
| 상담 문의 | 3건 | 10건 | 20건 |
| 신규 계약 (누적) | 1건 | 4건 | 9건 |
| 유지보수 구독 (누적) | 1곳 | 4곳 | 9곳 |

## 난이도 레벨 체계

홈페이지 복잡도를 다섯 단계로 나눈다. 각 레벨은 이전 레벨의 블록과 모듈을 그대로 쓰고 새 모듈만 더한다. 레벨을 올리며 만든 모듈은 공통 패키지에 등록해 이후 모든 업종이 재사용하고, 이 레벨 체계가 그대로 판매 상품 체계가 된다.

| 레벨 | 유형 | 새로 추가되는 모듈 | 대표 업종 | 착수 시점 |
|---|---|---|---|---|
| L1 | 브랜딩 소개형 (5~8페이지 정적) | 섹션 블록, 테마 토큰, SEO, 외부 링크 CTA(전화, 카카오톡, 네이버 예약) | 세무, 법률, 노무, 인테리어, 건축, 카페, 스튜디오, 제조 | 1~4주 |
| L2 | 상담 전환형 | PHP 공통 폼 API(상담, 견적), 개인정보 동의, 알림(메일, 카카오 알림톡) | 청소·방역, 인테리어 견적, 교육 상담, 병의원 상담 | 5~6주 |
| L3 | 콘텐츠 운영형 | 경량 관리자, 게시판, 공지, 칼럼, 시공사례 관리 | 법률 칼럼, 시공사례 갤러리, 학원 공지 | 7~9주 |
| L4 | 예약형 | 예약 슬롯과 승인, 일정 알림, 결제 연동(선택) | 필라테스, 미용실, 스튜디오, 펜션 | 10~12주 |
| L5 | 데이터형 | 회원, 검색·필터 DB, 외부 API 연동 | 부동산 매물, 프랜차이즈 가맹, 소형 쇼핑몰 | 13주 이후 |

### 레벨 진입 조건

- L2 착수: L1 템플릿 10개 이상, 공통 블록 30개 이상이 라이브러리에 등록된 상태.
- L3 착수: 폼 API가 3개 이상 사이트에서 2주 동안 장애 없이 운영된 상태.
- L4 이후: 이전 레벨 템플릿이 5개 이상 계약 또는 문의로 이어진 상태.
- 일정: 각 레벨의 첫 사이트는 모듈 개발을 포함해 3일로 잡고, 두 번째부터 하루 1개로 돌아간다.

## 90일 로드맵

생산, 시스템, 마케팅을 같은 주기로 진행한다. 시스템은 생산을 멈추지 않는 범위에서 가장 시간이 많이 드는 단계부터 자동화한다.

| 기간 | 생산 | 시스템 | 마케팅·영업 |
|---|---|---|---|
| 0주차 (준비 5일) | medical-dermatology를 기준 템플릿으로 정리 | 모노레포 이관, 스펙 표준, new·qa 명령, CI 배포 | 포트폴리오 사이트 오픈, SNS 계정 개설, 크몽·숨고 판매자 등록 |
| 1~4주 | L1 업종 15개 (평일 하루 1개, 금요일은 변형) | 스크린샷과 SNS 소재 자동 생성 | 신작 캐러셀 매일, 릴스 주 3회, 패키지 가격 공개 |
| 5~8주 | L1 변형과 L2 업종 15개 | 폼 API, 문의 자동 응답, 예약 발행 | 소액 타깃 광고 테스트, 블로그 SEO 글 주 2회 |
| 9~12주 | L2~L3 업종 15개 | 관리자, 진행 현황 자동 기록, S0~S8 일괄 실행 | 고객 사례 콘텐츠, 추천 프로그램, 유지보수 패키지 판매 |

## 주간 운영 리듬

평일 4일은 신규 업종, 금요일은 기존 템플릿 변형으로 주 5개를 만든다. 토요일은 지표 리뷰와 다음 주 준비에 쓴다.

| 요일 | 오전 | 오후 |
|---|---|---|
| 월~목 | 사이트 1개 생산 (S1~S4) | QA, 배포, SNS 소재 (S5~S8), 문의 응대 |
| 금 | 기존 템플릿 변형 1개 | 블록 리팩터링, 공통 모듈 개선 |
| 토 | SNS·유입·문의 지표 리뷰 | 다음 주 업종 4개 확정, 리서치 카드 초안 일괄 생성 |
| 일 | 휴식 | 예약 발행만 자동 진행 |

## 사람과 AI의 역할 분담

사람은 판단과 승인, 영업에 집중하고 반복 작업은 AI와 자동화가 맡는다. 승인 게이트는 G1 컨셉, G2 품질, G3 발행 세 곳이다.

| 영역 | 사람 (판단·승인) | AI·자동화 (생성·반복) |
|---|---|---|
| 기획 | 업종 선택, 컨셉 승인 (G1) | 리서치 카드 초안, 사이트 스펙 초안 |
| 제작 | 최종 디자인 확인 | 카피, 이미지, 데이터 파일, 블록 코드 |
| 품질 | 규제 문구 최종 확인 (G2) | lint, 빌드, Lighthouse, 링크·접근성·금지 표현 검사 |
| 배포·마케팅 | 발행 승인 (G3) | 커밋, 배포, 스크린샷, 캐러셀, 릴스, 캡션, 예약 발행 |
| 영업 | 상담, 견적 확정, 계약 | 문의 자동 응답, 견적서 초안, 진행 현황 기록 |

## 리스크와 대응

운영 초기에 생길 수 있는 문제와 대응 방법이다.

| 리스크 | 대응 |
|---|---|
| 이미지·폰트 저작권 | AI 생성 또는 상업용 라이선스 소스만 사용하고 출처를 site-spec에 기록 |
| 가상 업체가 실존 업체로 오인 | 데모 상단 배너와 SNS 이미지에 가상 업체 데모 표기, 상호는 검색으로 중복 확인 후 확정 |
| 의료·법률 광고 규정 위반 | 업종별 금지 표현 사전과 필수 고지를 스펙 표준에 포함, 실제 납품 시 심의 또는 전문가 검토 |
| 템플릿 획일화 | 업종마다 변형 2개 이상, 히어로 블록은 업종 전용으로 제작 |
| SNS API 승인 지연 | 승인 전에는 예약 발행 도구나 수동 업로드로 운영하고 소재 생성까지만 자동화 |
| 1인 운영 과부하 | 승인 게이트 외 단계는 자동화, 문의 응대 시간대를 고정 |
